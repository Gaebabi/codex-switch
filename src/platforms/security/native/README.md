# App-private encrypted Secret Service compatibility

The Linux package includes a separately named, dynamically linked LGPL-2.1-or-later libsecret0.21.8.2 build. [Pinned source manifest](libsecret.json), [complete source patch](libsecret-compat.patch), [license](../../../../licenses/libsecret.LGPL-2.1.txt), [build procedure](../../../../scripts/build-linux-secret.py). The upstream archive SHA256 is verified before extraction; only the declared source/patch is built. System libsecret, KWallet and GNOME Keyring are never replaced. GLib/libgcrypt remain system dependencies. Downstream distributions can rebuild/relink the shared library from these public sources and install the resulting compatible ABI next to the app. No source archive or binary is committed.

The transport remains the Secret Service `dh-ietf1024-sha256-aes128-cbc-pkcs7` algorithm, implemented by upstream libsecret/libgcrypt. There is no plaintext fallback or new cryptographic primitive. This wire protocol's1024-bit DH is inherited interoperability scope, not a modern general-purpose key-exchange recommendation. Enforced FIPS policy refuses the protocol rather than disabling the policy.

Three representation defects are fixed: public DH integers retain128 group bytes, satisfying KWallet's minimum width; a leading zero makes the value positive for KWallet5's signed QCA BigInteger decoder; and only for the UID/unique-owner-verified KWallet5 provider, HKDF input uses the minimal unsigned shared-secret representation produced by QCA/OpenSSL `DH_compute_key`. The129-byte positive form is the same unsigned integer, not a new group or weaker key. GNOME uses128 bytes and keeps upstream's padded shared-secret representation. This is decided before the single encrypted handshake; there is no retry/try-other-key/padding-error recovery. App-local native loading checks ABI1 and uses the absolute library path beside the executable, with no system-library fallback. KWallet6/KSecrets has a separate compatibility gate because newer upstream revisions normalize their shared secret differently; an unverified encoding is not guessed.

Both synchronous and asynchronous upstream session paths retain encrypted-only negotiation. The custom open entry point takes only a verified unique D-Bus owner and a validated boolean encoding mode, sets it before session negotiation, and refuses FIPS mode. Ownership, cancellable deadlines, locked/missing/ambiguous/invalid keys, exact32-byte secrets and no implicit unlock remain managed by the existing provider. CADL1 AES-GCM format, vault identity attributes and stored key bytes are unchanged; no credential migration is needed.

Native build verification compiles the exact patched upstream source into a separate test executable: RFC5869 case3 with a leading-zero-padded input proves KDE normalization; an independent padded-input reference proves GNOME derivation is unchanged;1024 real generated public keys retain unsigned/sign-safe width. The native provider suite separately performs1024 independent binary-key sessions, real save/reopen/tamper/lock/unlock/restart/concurrency/missing/timeout/offline checks. Test-only collection/PAM controls do not enter production. Actual target-OS results and app images are required before claiming support.

Source references: [Secret Service algorithm](https://specifications.freedesktop.org/secret-service/latest/ch07s03.html), [upstream libsecret](https://gitlab.gnome.org/GNOME/libsecret/-/tree/0.21.8.2), [KWallet session derivation](https://invent.kde.org/frameworks/kwallet/-/blob/v5.115.0/src/runtime/kwalletd/kwalletfreedesktopservice.cpp), [QCA OpenSSL implementation](https://invent.kde.org/libraries/qca/-/blob/v2.3.8/plugins/qca-ossl/qca-ossl.cpp).
