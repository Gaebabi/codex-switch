# Native connection restoration

Native OpenAI compaction is forwarded to OpenAI and its encrypted output is preserved. Earlier Switch builds incorrectly returned a local `codex-switch-history:v1:` reference for native compaction, which OpenAI cannot decrypt after the connection is restored. Before changing routing, restoration now identifies affected native conversations, validates their exact history segment boundaries and account, and requires every referenced summary in the protected history store. After normal shutdown, the official app-server compacts each affected conversation with that summary expanded at its original input position. Later messages and tools remain in place. Only a durable native compaction permits routing restoration; failure leaves the original history and connection available for recovery.

The recovery endpoint is temporary, bound to loopback, authenticated by the existing sign-in, and restricted to one prepared native conversation/model and compaction requests. It cannot execute ordinary turns or image requests and is never written into root configuration. Recovery appends through Codex itself; it does not edit rollouts or databases. A completed conversation is skipped on retry. Custom-model conversations retain their separate profile and are not silently retargeted.

Normal Codex connects to its original OpenAI endpoint independently of Switch. Custom models use the separate `codex-switch` CLI profile described in [model providers](MODEL_PROVIDERS.md). The combined desktop profile is retired: its global `openai_base_url` override sent every OpenAI request through Switch's in-process gateway, so closing Switch broke native chats.

**Settings > Codex profile > Default — restore and restart** restores the connection and catalog recorded before the old desktop integration. The apply-Switch action has been removed. Both validation and application reject a saved request to activate that retired profile before starting a gateway or modifying configuration. Its enum value remains readable for existing recovery records.

Restoration uses the existing same-account restart coordinator. Before shutdown, the actual CLI validates the original catalog in a disposable credential-free home. After normal shutdown, validation runs again and the official configuration RPC writes only recorded Switch-owned keys using `expectedVersion`. Already-original values are accepted; divergent owner edits stop the operation. Unrelated settings, comments, sign-in, provider keys and chat history remain intact. Supported explicit native reasoning settings are preserved; an unsupported root effort is removed using actual model capabilities.

The management RPC uses a temporary private control catalog so restoration remains available even when the old Switch catalog contains an invalid null boolean. That override is never saved. After restoration the combined model cache is invalidated so the next native load obtains its own catalog. Model/provider registrations and their fixed aliases, visibility and reasoning settings remain in the encrypted store.

Then prepare the custom profile in **Model providers** and use **Open custom terminal**. The profile shares the existing official sign-in file without copying it. Its connection, catalog and transport overrides apply only to a process explicitly started with `--no-daemon --profile codex-switch`. Normal Codex continues with Switch completely stopped. Custom requests require Switch and fail while it is unavailable; they never fall back to another model or native OpenAI.

An already-running Codex process can retain the old endpoint in memory, which is why the explicit recovery action includes a normal restart. Existing custom-model chats keep their IDs and files and require their custom profile/backend to continue. Restoration does not silently convert their model or rewrite encrypted history. The separate CLI's static model catalog refreshes when that terminal is reopened; editing visibility no longer claims a live update in the normal desktop picker.

Verification distinguishes legacy-fixture compatibility, actual native parser/restoration, normal and custom process isolation, Switch-off requests, production UI structure, and real owner acceptance. Historical combined-picker evidence remains in [the former desktop integration notes](DESKTOP_LIVE_MODELS.md), not as the current supported connection architecture.
