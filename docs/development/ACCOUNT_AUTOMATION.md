# Account reauthentication and automatic switching

The per-account warning action opens the existing official browser login flow for that account. A confirmed login rejection changes the account action to **Sign in** and replaces current quota figures with dashes. The encrypted vault retains usage history and remembers the rejection across restarts. Ordinary refresh failures retain the last usage reading and show the refresh error on hover. A different account identity is rejected before registration is changed. Successful reauthentication updates the original registration, retaining its key, alias and usage history. Canonical desktop credentials are applied only through the existing switch action.

The **Auto Switch** toolbar menu contains a persistent On/Off toggle and the next eligible account, with automation disabled by default. Select a remaining-usage threshold of 5, 10 (default), 15 or 20 percent. The evaluator runs after the regular 60-second refresh. It requires one current account, successful observations no older than two minutes, matching bucket/window identities and positive durations, and a candidate with every reported window at least five percentage points above the threshold. Missing/zero/negative durations do not qualify even when both accounts omit the same value. Duplicate or blank quota bucket IDs make a profile ambiguous: a source blocks automatic selection/forecasting and a candidate is skipped while valid alternatives remain eligible. Original quota snapshots remain unchanged; ambiguity is not merged, guessed or accepted through a dictionary exception. A source at exactly the threshold does not trigger. An exhausted source can switch away; restricted candidates cannot be selected. Displaying a different quota in a card does not change this policy. Stale, failed, refreshing, missing or invalid quota data never initiates a handoff. A stopped/disconnected desktop, active login/switch/query, five-minute persisted cooldown or pending recovery also blocks automatic selection.

Choose **Expires soonest first** (default) to consume the earliest known subscription date among eligible accounts, then maximize the lowest remaining percentage across quota windows. Past dates retain priority when fresh usage still qualifies; unknown dates follow known dates, and equal/unknown dates use remaining usage and stable account keys. A past date never overrides a server restriction or creates entitlement. This compares reported percentages, not inferred token counts or purchased credits. **Custom priority** chooses the first eligible account in the saved order. Each account's menu has **Priority 1/2/...**; choosing a position moves that account there, shifts the others and selects custom mode without enabling automation. The menu also shows the next eligible account even before the current quota crosses its threshold, using the same candidate guards/ranking. This read-only forecast does not reserve or start a handoff, can change after a refresh, and retains an existing pending-recovery target. It refreshes on menu opening and normal UI updates; there is no extra poller. No eligible account is explicit. The toolbar tooltip retains On/Off state and the forecast. The menu also shows the complete custom order. Invalid or restricted high-priority accounts are skipped; priority never bypasses freshness, minimum remaining, cooldown or recovery guards. Unranked/new accounts follow saved ranks in stable key order. Returning to automatic mode preserves the saved custom order.

On Windows, manual account cards offer **Open** or **Focus**. Each additional account has a private native home and Electron profile on the same machine. Chat history belongs to that account window. Open discovers the window from its executable, profile argument and process creation time. An existing account window confirms the selected user and workspace through its live app-server before Switch brings it forward. Closing and reopening Switch rediscovers running windows. The dashboard subscribes to active chat counts for verified account windows. A login change or disconnection invalidates that observation. This view shares activity counts and keeps each account's conversation content in its own home.

Automatic switching and credit protection manage the primary session. Separate account windows use manual mode with credit use allowed. Existing recovery and login application actions remain explicit. Removing a registration for a closed managed window removes its file login and retains its local chat history.

The Windows dashboard saves tank positions by account key in the encrypted vault. Drag the handle at the start of a tank header or use **Move card** in the account menu. The dashboard keeps the chosen order across restarts and adds new accounts at the end. Automatic switching keeps its own priority list.

Windows status notices display a remaining-time bar and a close button. Ordinary notices expire after eight seconds and warnings expire after fifteen. Dismissing a recovery notice leaves the recovery action on the account card.

Coordinated account handoff saves checkpoints for chat backup, normal shutdown, credential application, native launch, IPC discovery and chat resume. The switch saves a checkpoint before shutdown or credential application. Transient failures share up to **two additional retries**, saved before each one-second retry wait. An unconfirmed shutdown or launch that reaches its deadline stops for explicit recovery. Once the native desktop is observed running, IPC and chat retries stay in their own stages. A switch with no chats left to resume completes upon observing the desktop. Each retry checks account identity where it authorizes an action. The coordinator recognizes credentials already applied and only observes a Continue whose delivery is uncertain.

Windows shows the current step, remaining stage time, chat count, retry number and a cancel action in the account header. The budgets are 45 seconds for preparation or normal shutdown, 60 seconds per name backup or account application, 40 seconds for launch, 30 seconds per connection attempt and 90 seconds per chat resume. Model-profile operations have a separate 180-second budget. Cancellation waits for the current operation to settle. After confirmed shutdown and before any launch request, cancellation or a failed application can trigger one 35-second safety attempt to reopen the verified desktop. A failed automatic handoff disables further automation.

**Recover** remains available on the recorded account even while the original account is current. Clicking it starts a fresh two-retry budget. An explicit switch can replace a manual, pre-application same-account restart only when it has zero saved chats and no model or credit action. Recovering that empty restart also captures the current chats again. The original checkpoint stays in place until the same source login and fresh chat capture are both verified.

During a same-account restart, Switch reopens each captured chat and confirms that the native client loaded it. Codex controls automatic continuation. Active goals also retain native continuation ownership during account handoff, including while goal metadata is being restored.

On Windows, a verified primary Codex window that started after an empty manual same-account restart request resolves that pending request. Switch checks the current login and preserves any request that recorded chats, applied credentials or model settings, or involved credit protection.

The observed Windows desktop 26.1117.4957.0 used private stdio for its app-server. Switching a saved login in the open window requires both a connection to that server and an operation that can adopt the target login. In a disposable two-login test, a second app-server read login B after the credentials file changed. The original server still reported A through `accountSession/list`. Calling `accountSession/switch` on the original server with B's actual session and workspace IDs returned JSON-RPC error `-32600` on both 0.167.0-alpha.4.1 and 0.171.0-alpha.13. On 0.167.0-alpha.4.1, account and auth refresh requests also left A active. Verify a change of identity on the server serving the desktop before reporting completion.

After the utility restarts, an interrupted automatic plan with no retry reserved gets one persisted recovery attempt, counted within the same two-retry budget. A plan that has already reserved a retry requires manual Recover after a utility restart. Explicit user/lifetime cancellation prevents automatic recovery and retains manual Recover. No indefinite timer/restart loop is allowed. Already completed chats and original Continue message identities survive recovery; ambiguous delivery retains the existing no-resend policy. Disabling automation affects future selection, not a checkpointed handoff already in progress. Recovery cannot guarantee launch when the client is missing or its IPC remains unavailable; the pending plan and error remain available for a later retry.

Both UIs distinguish **Renews** from **Expires** and show **Days left** in Korean calendar days. Subscription data is read from the official first-party `GET /backend-api/accounts/check/v4-2023-04-27` endpoint using the selected account's managed access token and `ChatGPT-Account-ID`. This internal endpoint is observed in the official desktop26.1106.6628.0 billing flow; it is not a documented public API. Only the exact matching account entry is accepted. Active auto-renewal uses `entitlement.renews_at`; a non-renewing subscription uses `expires_at`, then `cancels_at` when expiration is absent. Missing dates stay unknown and malformed dates fail explicitly. Successful queries, including inactive results, replace the encrypted billing snapshot. Login claims are not current billing evidence: even successful token refresh can return an old period. Credential synchronization cannot overwrite a verified billing snapshot. Identity/revision guards discard obsolete results; a billing failure keeps the previous successful timestamp and displays an error while quota refresh remains available. No extra token rotation, account switching, browser cookies or owner restart is needed.

The shared presenter preserves official numbered Pro names rather than collapsing them into one family. [Official pricing](https://learn.chatgpt.com/docs/pricing) and [official plan names](https://learn.chatgpt.com/docs/dots#access), checked 2026-10-24, distinguish **Pro 100**, **Pro 200** and **Pro 500**. The official desktop26.1016.8622.0 `plan-names` module's `planUpgradeModal.subscription.numberedTiers` message maps `prolite` to **Pro 100**, `pro` to **Pro 200**, and `promax` to **Pro 500**. Existing explicit numeric/underscore aliases retain the matching tier. Legacy `team` displays as **Business**. This only formats the label: original account entitlements remain unchanged, and the number is the official tier name rather than a claim about the account's actual charge or billing currency. Unknown future identifiers remain visible.

## Verification

The toolbar names account switching in every bundled language. Its own column allows long labels to wrap without covering centered session counters. Windows offscreen layout checks cover nine languages, both states, the500×360 minimum and two-digit session counts; these do not show or interact with a native window.

Run the fictional account/restart contracts on Windows:

```text
dotnet run --project tests/account-automation/CodexSwitch.AccountAutomation.Tests.csproj -c Release --no-launch-profile -p:UseSharedCompilation=false
```

Use each environment's required output routing for all builds. The Windows workflow runs this suite in addition to existing internal checks. Its disposable account fixture uses user-local temporary storage with native ACL ownership. Machine-wide redirected temporary directories can reject WRITE_OWNER; do not weaken the production ACL contract to make such a fixture pass.

Validation includes83 fictional encrypted identity/quota/recovery contracts and28 actual native Windows feature/control assertions.
