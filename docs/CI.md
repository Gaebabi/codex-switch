# PR verification

Source1.34.0 extends the two native Linux jobs with the pinned official desktop package/embedded CLI and locked standalone CLI. Explicit disposable-runner guards allow installation/test-created system policies only on those isolated CI workers and refuse pre-existing policy files. Each native architecture passes94 executable-trust/configuration-policy assertions (including14 native trust checks), existing GNOME18/SQLite26/protocol10 and actual source-window12. Windows/Mac protocol9 preserves the existing isolated file-credential RPC behavior. Native binary/selected-home policy approval is distinct from full desktop resources, active peer identity, project/runtime contexts and authenticated handoff. [Client proof and limits](evidence/linux-client/README.md).

[Verify](../.github/workflows/verify.yml) runs on PRs, pushes to `main` and manual dispatch. It uses read-only contents permission, SHA-pinned official actions, non-persistent checkout credentials and disposable hosted runners. No account/signing secrets, privileged fork events or release publication.

[Linux native](../.github/workflows/linux-native.yml) separately declares actual Ubuntu24.04 x64/arm64 GNOME Keyring runs with a private D-Bus/XDG environment. Source1.33.0 storage promotion requires both native jobs at the exact reviewed head in addition to all four Verify jobs. [Native commands, isolation and incomplete support gates](development/LINUX.md). A portable Ubuntu pass is not a native keyring or application acceptance result; KDE/KWallet and Linux client/handoff/packages remain separate.

The Linux jobs also publish the source preview for the actual runner, inspect the complete runtime, run its synthetic own-window mode on X11/Xvfb and export12 lossless native PNGs per architecture. XID-only capture cannot fall back to desktop capture or managed rendering. Common export removes metadata and binds the PR head revision; checkout explicitly selects that head. Source account/client/handoff actions remain disabled. These screenshots complement the separate18-check provider suite and do not certify real account/handoff, native Wayland or full desktop-session support.

Source1.33.1 additionally runs the published Linux executable's explicit-home queue diagnostic through `verify-queues.py` on both native architectures, including committed WAL visibility on non-writable database/WAL/SHM files and parent directory. The writable reports subdirectory is explicit. Presence/hash comparisons protect database/WAL content; SQLite SHM read coordination is a separate behavior. Linux26 fixture assertions and native protocol7 are gates alongside existing Windows/Mac SQLite23/protocol6. This does not connect to installed-client IPC or use real account/home data.

Source1.30.0 CI also runs the actual published Windows/Mac app in an isolated evidence mode and captures only its own native window with fictional profiles. Sanitized PNGs/runtime/architecture manifests are retained as14-day artifacts after validation; no raw desktop, user home, account secret or binary Release is published. Mac evidence mode explicitly selects software rendering on virtual runners; it does not prove Metal/GPU coverage. Complete package inspection checks .NET10.0.13 included runtimes and RID. Native window execution is distinct from real login/switch/resume and Linux acceptance.

Language packs additionally run structural/source-key checks and the production parser/culture/installation test project on all three hosts. Nine built-in catalogues are complete; custom-pack rejection, English fallback, integer plural rules, UTF-8/BOM, restart reload and RTL culture are exercised. [Localization guide](LOCALIZATION.md)

Source1.30.1 apps/tests consume one UI-neutral core assembly. Contract checks verify its identity/native dependency boundary and preserve installed catalogue bytes/selection when the platform writer refuses. Ubuntu additionally confirms unsupported vault/discovery fail before entering a Windows path. Native Windows/Mac UI evidence remains required after extraction; Ubuntu portable contracts are not Linux desktop support.

Source1.31.0 extracts native vault/private-file primitives into one `CodexSwitch.PlatformSecurity` assembly; complete packages require both core and security DLLs. `tests/platform-security` runs native DPAPI on Windows, Keychain/AES-GCM on both Mac architectures, and POSIX/file/unsupported-encryption contracts on Ubuntu. It uses unique disposable directories and synthetic plaintext only; native Mac keys use the existing diagnostic-only cleanup restriction. Native key tests cover cache-release reload, tamper/truncation and missing-key rejection, not desktop login or an unlocked/locked keychain UI matrix. Linux encryption remains unsupported until #5.

Source1.31.1 similarly requires the new `CodexSwitch.DesktopClient` DLL. Its standalone tests verify assembly ownership, invalid-ID/missing-client refusal and unsupported lifecycle calls on Ubuntu. These tests do not start or stop an installed client; Windows's existing disposable parent/child handoff regression separately checks production Restart Manager/coordinator behavior. Native app screenshots remain required on both supported OSes.

Source1.31.2 requires Protocol/Sqlite DLLs as well. `tests/protocol` verifies independent assembly ownership, unstarted observations remaining unavailable, missing/corrupt read-only files and unsupported platform refusal. Existing native `verify-queues.py` fixtures pass through the extracted implementations and check committed WAL visibility, filtering/deduplication and unchanged database/WAL bytes. Neither synthetic fixtures nor native app screenshots certify installed-client authentication or live handoff.

Source1.31.3 also requires the Hardware DLL. `tests/hardware` checks preserved drive JSON, pending unknown state, wrong-OS native refusal and actual supported-OS non-elevated read-only sampler contracts. Hardware identities/measurements are not exported to test logs. Existing temperature29 parsing/sensor selection tests now reference the same assembly; unavailable sensors remain unavailable. System.Management updates are proposed for `/src/platforms/resources`, their new owning dependency directory.

Source1.32.0 additionally requires Application.dll for both apps and Desktop.dll for Mac. Language/temperature/handoff/rendering consume the single application integration project rather than linked copies. `tests/composition` checks independent owners, absence of direct native imports and host types in UI, embedded resources and deferred appearance. Windows/Mac native mode also shows the actual shared UI with synthetic accounts/pending resources and verifies ordinary trayless close/disposal without creating a data/home directory. These probes complement the published app's existing native screenshot/menu/layout tests; they are not Linux or real-account acceptance. Avalonia remains pinned11.3.22, with Dependabot following `/src/desktop`.

Temperature contract checks run on all three hosts: production storage parsing, volume/device/channel identity, partial coverage, invalid/unavailable/stale readings and multilingual formatting. Hosted CI does not claim physical temperature sensors. [Temperature support](TEMPERATURES.md)

Tool dependencies are pinned in [requirements-dev.txt](../requirements-dev.txt), SDK in [global.json](../global.json). Windows checks require the actual official Codex CLI for app-server login cancellation and isolated credential-switch initialization; CI installs version 0.162.1 from the [locked development prerequisite](../tools/ci-codex/package.json), with lifecycle scripts disabled and its exact native executable path selected. No desktop install or successful browser authentication is required. Those checks do not fake the app-server protocol or use a real account.

Dependabot proposes Actions, Windows/Mac NuGet, Python and the locked CLI prerequisite updates for review. This is not a complete lockfile of every project dependency or a bit-for-bit reproducibility claim. [GitHub security guidance](https://docs.github.com/en/actions/reference/security/secure-use)

The public audit covers selected credential formats, private tracked paths, non-example emails, local checkout paths and media metadata, including YAML/TOML/editor settings. `--tree-only` explicitly omits history; default full audit retains reachable blobs/commit identity checks. Historical generic checkout paths remain detectable. Never report a tree pass as a full-history pass or suppress findings to make CI green.

Required-check branch protection/signing are separate repository settings. Future release workflows require separate publication/signing review. [Roadmap](PLATFORM_SUPPORT_PLAN.md)
