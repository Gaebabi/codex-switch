# Folder storage monitoring

Windows measures folder allocation only while the main window is visible and not minimized. Tray startup does not start recursive folder measurement. Hiding or minimizing the window cancels the current traversal; reopening resumes using retained snapshots and queued changes. Existing values remain available while measurement is paused. Lightweight drive capacity and I/O counters continue independently.

The visible scan shares one metadata budget across all configured drives: at most 32 query batches or allocation lookups per second, with a rest period of at least four times each query's elapsed work before the next query. Root metadata, watcher connection, directory batches and sparse/compressed or hard-link allocation reads use that budget. It also covers the initial scan and failed queries. Cancellation interrupts a budget wait. Cached directory/root reuse consumes no query budget. A single blocking filesystem call can finish after its requested window; this limits Switch's query scheduling rather than guaranteeing a whole-volume activity percentage. Large trees continue toward a complete allocated-size measurement instead of being truncated at an arbitrary file/depth limit.

A spinner appears immediately to the right of a drive's capacity label while its folder measurement or watcher setup is active. It clears after completion/cancellation and does not spin for unrelated drives. Its animation stops when the indicator is hidden.

The Windows gauge keeps drive metadata above a separate12px allocation bar. Tracked folders use opaque colors with diagonal texture and visible separators; other used space is neutral and free space stays unfilled. Wide folder segments show their share directly. Small segments retain their measured width and expose the exact share on hover. Drives without tracked folders use the same used/free scale.

CPU, memory, GPU and VRAM use the same separated metadata/current-percentage bars. Quarter marks help compare utilization; missing readings stay empty with an unavailable value. Historical trend graphs remain in the resource tooltip rather than behind the text.

On Windows, open **Drive settings**, add folders below a drive, choose each color, and save. Local and mapped network drives are supported. The existing drive bar then partitions its total capacity into tracked folders, other used space, and free space. Hover over a colored segment for its path, allocated size, percentage of the drive, and measurement state. Click it to open that folder in File Explorer; other-used and free-space segments open the drive root. Segment controls remain stable during periodic refresh so an open tooltip does not disappear. Removing folders retains the other folders' colors. Settings survive application restart in the existing account vault.

Up to eight folders can be tracked per drive. Paths must be absolute and inside that drive. Parent/child paths cannot overlap. Reparse points, including symbolic links and directory junctions, are excluded; selecting a linked root is reported as unavailable. File identities prevent hard links from being counted twice across the tracked folders. Sizes use Windows allocated file bytes, including hidden files, rather than summing logical file lengths. Filesystem metadata and untracked files remain in other used space.

Folder measurements run independently in the background immediately after configuration changes. The initial measurement reads the tracked trees once and retains directory allocation snapshots in memory. Windows filesystem notifications then invalidate only the affected directories; notifications are grouped for two seconds, and unchanged subtrees are not enumerated again. Unchanged tracked roots also retain their readings without any root/ancestor metadata queries, even when another tracked folder changes. Allocation totals for unrelated drives are reused. New or renamed trees are measured at their new paths, deleted entries are removed, and hard-link allocation is still counted once per drive. Idle folders have no recurring full-tree scan. Very large initial measurements may take longer than one minute.

Each completed folder is published immediately. Scans do not overlap or delay the existing disk I/O samples or UI thread. Removed configurations cancel pending scans, and version checks prevent old results from reappearing. Lost notifications invalidate the affected root and reconnect its watcher before rebuilding that snapshot. Deleted roots are watched through an existing ancestor until they return. Unavailable watchers are reported as partial coverage; only failed observations and watcher connections are retried every sixty seconds. Empty, missing, inaccessible, partially readable and pending folders remain distinct. No files are changed and no elevated permissions are requested.

Windows directory queries retrieve file identities and allocated sizes in batches using FILE_ID_BOTH_DIR_INFO. Sparse/compressed files retain their explicit physical-allocation query. Drivers that explicitly do not support that directory information class use individual file queries. Extended native paths prevent deep build/cache trees beyond MAX_PATH from being silently omitted. The metadata layout and SMB support follow the [Windows directory record](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_both_dir_info) and [handle-information API](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getfileinformationbyhandleex).

The drive-capacity sample and folder scan are not an atomic filesystem snapshot. Folder segments are bounded by the currently observed used space; their legend retains the measured values. Files changing during a scan can produce a partial measurement. The Windows editor implements folder management; other desktop platforms preserve saved folder preferences and explicitly report unsupported allocation measurement.

Validation uses disposable real files, compressed/sparse allocation compared with an independent Windows API, hard links, junctions, long paths and directories spanning multiple metadata buffers. It also checks cancellation, early publication, unchanged-snapshot reuse, one-directory invalidation, hard-link growth, rename/replacement, lost-notification recovery, real filesystem notifications, deleted-root recovery, sixty-five seconds of idle monitoring, immediate removal and prevention of stale results. The actual settings controls, selected color swatches, gauge and compact tooltip are rendered in Korean/English and both themes; click contracts verify exact folder/root targets and control stability across refresh. These fixtures do not scan personal folders. Separate owner-authorized installation and storage inventories are distinguished from these isolated fixtures.
