# Folder storage monitoring

Windows measures folder allocation only while the main window is visible and not minimized. Tray startup does not start recursive folder measurement. Hiding or minimizing the window cancels the current traversal; reopening resumes using retained snapshots and queued changes. Existing values remain available while measurement is paused. Lightweight drive capacity and I/O counters continue independently.

The Windows folder index now survives process restarts in the existing application's private `folder-index/allocation.sqlite3` cache. Saved readings are restored before the detailed index is loaded; they remain explicitly cached until root identity and change tracking have been checked. The first measurement is still required once, but completed directory work is committed during that measurement. An interrupted first index resumes saved work rather than enumerating the same directories again.

NTFS change-journal identities and cursors allow the ordinary application to replay changes made while it was closed. Parent and file identities locate affected directories and hard-link aliases. Unchanged user trees need no repeated directory enumeration on restart; reading and accounting for the index's own private cache files remains necessary. Replaced roots, lost journal ranges and changed journal identities invalidate affected data. The index stores physical file references and maintains allocation totals incrementally; a small change does not require walking every cached file again.

If a local drive needs journal activation or access approval, a lock appears immediately beside its capacity. Activate it to request Windows approval for that drive. A separate short-lived setup command enables a missing journal with a128MiB target and32MiB allocation delta; it does not resize an already available journal. The account application keeps ordinary permissions and rechecks access before removing the lock. Cancelling or failing approval leaves the lock available and clears the busy state. A corporate restriction may still prevent ordinary access after approval; that failure stays visible. Unsupported filesystems and remote journal APIs are shown separately and do not trigger pointless elevation.

Right-click a drive to rebuild its folder index. Filesystems without supported change tracking retain explicitly cached readings across app exits and can be rebuilt manually; live filesystem notifications still identify changes while the application is running. An invalid index stops indexing and reports an error instead of spinning. Explicit rebuilding preserves the rejected database with an `.invalid-` suffix before creating a replacement. Index metadata remains separate from account/provider vaults, authentication, Codex settings and chats.

The visible scan shares one metadata budget across all configured drives: at most 32 query batches or allocation lookups per second, with a rest period of at least four times each query's elapsed work before the next query. Root metadata, watcher connection, directory batches and sparse/compressed or hard-link allocation reads use that budget. It also covers the initial scan and failed queries. Cancellation interrupts a budget wait. Cached directory/root reuse consumes no query budget. A single blocking filesystem call can finish after its requested window; this limits Switch's query scheduling rather than guaranteeing a whole-volume activity percentage. Large trees continue toward a complete allocated-size measurement instead of being truncated at an arbitrary file/depth limit.

A spinner appears immediately to the right of a drive's capacity label while uncached directory measurement is active. Cached traversal, permission requests and idle waits do not keep it spinning. It clears after every work slice, completion, cancellation and failure, and does not spin for unrelated drives. The tooltip reports indexed folder/file counts so a large first index shows actual progress. Its animation stops when the indicator is hidden.

The Windows gauge keeps drive metadata above a separate12px allocation bar. Tracked folders use opaque colors with diagonal texture; other used space is neutral and free space stays unfilled. Wide folder segments show their share directly. A positive allocation smaller than one screen pixel gets one colored pixel, with separators reserved for wider segments. The tooltip retains the actual allocation and share. Drives without tracked folders use the same used/free scale.

CPU, memory, GPU and VRAM use the same separated metadata/current-percentage bars. Quarter marks help compare utilization; missing readings stay empty with an unavailable value. Historical trend graphs remain in the resource tooltip rather than behind the text.

On Windows, open **Drive settings**, add folders below a drive, choose each color, and save. Local and mapped network drives are supported. The existing drive bar then partitions its total capacity into tracked folders, other used space, and free space. Hover over a colored segment for its path, allocated size, percentage of the drive, and measurement state. Click it to open that folder in File Explorer; other-used and free-space segments open the drive root. Segment controls remain stable during periodic refresh so an open tooltip does not disappear. Removing folders retains the other folders' colors. Settings survive application restart in the existing account vault.

Up to eight folders can be tracked per drive. Paths must be absolute and inside that drive. Parent/child paths cannot overlap. Reparse points, including symbolic links and directory junctions, are excluded; selecting a linked root is reported as unavailable. File identities prevent hard links from being counted twice across the tracked folders. Sizes use Windows allocated file bytes, including hidden files, rather than summing logical file lengths. Filesystem metadata and untracked files remain in other used space.

Folder measurements run independently after configuration changes. The initial measurement reads tracked trees in bounded cancellable slices and checkpoints directory snapshots, file allocations and pending changes together. Windows filesystem notifications wake the indexer; journal replay identifies actual changes and ignores timestamp-only activity that cannot change allocation. Notifications are grouped for two seconds, and unchanged subtrees are not enumerated again. Cached readings remain available between slices. Root/ancestor identity is checked when restoring an index, rather than repeatedly while unchanged monitoring is idle. Allocation totals for unrelated drives are reused. New or renamed trees are measured at their new paths, deleted entries are removed, and hard-link allocation is counted once per drive. Idle folders have no recurring full-tree scan. Very large first indexes can take longer than one minute and retain completed work when closed.

The monitor retains each drive's journal status across scan slices. A filesystem change triggers journal replay only on the affected drive with a readable journal. A drive without journal support, such as a mapped drive, can finish its first bounded measurement and update changed directories from live notifications. The monitor rechecks journal support when the watcher resets or the user requests a refresh. Idle index retries consult known failures and reuse successful directory snapshots.

Metadata changes on a tracked folder itself recheck its identity and listing access. Directory timestamp notices generated by traversal do not invalidate their parent listings. Structural changes, file allocation changes, and attribute or security notifications still refresh the affected data. A routine file change does not discard the folder's directory snapshots.

Each completed folder/work slice is published immediately. Indexing does not overlap or delay existing disk I/O samples or the UI thread. Removed configurations cancel pending work, and version checks prevent old results from reappearing. Lost notifications use retained journal coverage where available; missing ranges require rebuilding affected data. Deleted roots are watched through an existing ancestor until they return. Unavailable watchers report partial coverage; failed observations and connections retry on the existing sixty-second schedule. Empty, missing, inaccessible, partial, cached and pending readings remain distinct. Tracked file contents are unchanged. Administrative approval is requested only after the user activates the journal-setup lock.

Index-owned SQLite writes are excluded from change invalidation to prevent self-triggered indexing. Their actual allocation is still measured and included when the cache directory is inside a tracked folder. Private cache maintenance is separate from recursive user-folder traversal.

Windows directory queries retrieve file identities and allocated sizes in batches using FILE_ID_BOTH_DIR_INFO. Sparse/compressed files retain their explicit physical-allocation query. Drivers that explicitly do not support that directory information class use individual file queries. Extended native paths prevent deep build/cache trees beyond MAX_PATH from being silently omitted. The metadata layout and SMB support follow the [Windows directory record](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_both_dir_info) and [handle-information API](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getfileinformationbyhandleex).

The drive-capacity sample and folder scan are not an atomic filesystem snapshot. Folder segments are bounded by the currently observed used space; their legend retains the measured values. Files changing during a scan can produce a partial measurement. The Windows editor implements folder management; other desktop platforms preserve saved folder preferences and explicitly report unsupported allocation measurement.

Validation uses disposable real files, compressed/sparse allocation compared with an independent Windows API, hard links, junctions, long paths and directories spanning multiple metadata buffers. It also checks cancellation, early publication, unchanged-snapshot reuse, one-directory invalidation, hard-link growth, rename/replacement, lost-notification recovery, real filesystem notifications, deleted-root recovery, sixty-five seconds of idle monitoring, immediate removal and prevention of stale results. The actual settings controls, selected color swatches, gauge and compact tooltip are rendered in Korean/English and both themes; click contracts verify exact folder/root targets and control stability across refresh. These fixtures do not scan personal folders. Separate owner-authorized installation and storage inventories are distinguished from these isolated fixtures. Detailed acceptance is recorded in [current status](development/STATUS.md).
