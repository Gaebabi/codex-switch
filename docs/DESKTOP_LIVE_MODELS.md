# Live desktop model selection

Historical integration, retired on 2026-11-13. The combined desktop profile made native OpenAI requests depend on Switch's process. New activation is disabled and the UI offers native restoration only. Custom models use the separate CLI profile; its static catalog is loaded when that terminal starts. The details and acceptance records below describe previous combined mode and legacy compatibility. See [current native restoration](DESKTOP_MODEL_PROFILES.md).

After applying the Codex Switch desktop profile, Codex lists each enabled custom model as **Codex Switch (model ID)**. Each entry uses its existing fixed `cs_` provider/model alias, so selecting one chat's model does not retarget another chat. The desktop and app-server stay running. Each model advertises its own reasoning levels and default; supported explicit effort choices remain intact. Requests in progress retain their original route snapshot.

Switch's toolbar uses one vector sliders icon. Its popup groups registered models by provider and toggles their visibility in Codex. All registered models start enabled; saved visibility survives rediscovery of the same endpoint/model. Adding, removing, renaming providers and changing model metadata publish immediately through the same serialized refresh path. Hidden entries remain available for existing chats. Deleting a provider or model removes its fixed entry and old requests fail explicitly instead of selecting a substitute.

The legacy `codex-switch` ID stays hidden in the catalog and continues to use the saved global selection for existing chats. Chat files and defaults are not rewritten. Live confirmation compares the entire owned ID set, names, visibility, modalities and reasoning capabilities; a stale add, delete or toggle cannot be confirmed from one matching item.

OpenAI conversation history can contain native `additional_tools` events. Standard custom-model Responses endpoints may reject these as unsupported input items. The gateway moves their exact tool definitions into the request's standard `tools` array, deduplicates identical definitions and retains the original order/content of messages and tool calls. Conflicting definitions fail explicitly instead of choosing a schema. Native OpenAI requests and saved chat files remain unchanged. This conversion is distinct from encrypted compaction and reasoning handling.

## Initial activation and older profiles

Use **Codex profile → Codex Switch — apply and restart** once, when the current work is idle. This explicit action changes the native endpoint to Switch and removes the root static `model_catalog_json` override. It preserves the native model documents and default. Higher-priority static catalog overrides are refused before shutdown. Default restoration retains the original static catalog when one existed.

Older Switch profiles loaded a JSON catalog at app-server startup. Editing that file or invalidating the renderer cannot replace the already loaded static catalog. They require this one-time migration; subsequent backend selections do not restart Codex. A saved legacy receipt alone does not enable live refresh, and installing a Switch update does not reactivate a manually restored Codex configuration.

## Refresh contract

Selections are serialized with provider and reasoning edits. Switch validates and publishes its owned catalog snapshot, removes the native regenerable `models_cache.json`, then broadcasts `query-cache-invalidate` with the prefix `["models", "list", "local"]` through the existing desktop IPC connection. No chat settings, authentication files, encrypted history, executable or ASAR file are changed.

The native app-server fetches `/models` when that cache is absent. Switch retains the complete native catalog for its existing five-minute lifetime, scoped to the signed-in identity and client version, and appends the current fixed-model metadata and hidden legacy entry to each response. Thus model selection need not wait for an external catalog fetch. Explicit catalog discovery still fetches authoritative metadata.

Switch observes the regenerated cache for up to ten seconds to confirm the complete owned model set and capabilities. After a 500 ms foreground budget, the picker becomes usable while confirmation continues in the background. A late response carrying previous capabilities is invalidated and requested again. A new selection or manager shutdown cancels and drains the previous confirmation. Pending, confirmed, deferred and failed results are distinct; missing cache bytes or an IPC broadcast alone do not prove that the renderer refreshed. If confirmation is deferred, open the Codex model picker and retry the selection if its options remain stale. A missing desktop IPC connection does not launch or restart Codex. Malformed or linked cache files are preserved and reported; Switch never rewrites the native client's opaque identity or fabricates a replacement cache.

## Evidence and limits

The refresh points were inspected in Codex desktop 26.1106.6628.0 and tested with its native CLI 0.167.0-alpha.4.1. The shipped app receives external `query-cache-invalidate` broadcasts and forwards them to renderer query invalidation. The model-query prefix is `["models", "list"]`, followed by the host. The built-in provider reload restarts the app-server and is deliberately not used for per-selection refresh.

Disposable native app-server tests distinguish static catalogs from dynamic catalogs. They verify repeated selection, reasoning override save/clear, rediscovery and late-response correction in the same running process, unchanged native model documents and authentication, and legacy broken-catalog restoration. Named-pipe tests verify the actual notification frame without contacting the owner's app. These checks are distinct from clicking the installed native desktop picker or sending real provider inference.

The owner-authorized 2026-11-13 native desktop check used separate storage and processes. Selecting Qwen, Gemma and Qwen again changed the visible reasoning control from three choices to one and back to three while the desktop and app-server identities remained unchanged. Qwen's Light, Medium and Extra High choices were exercised. The owner profile was then explicitly applied through the production apply-and-restart action; the original desktop restarted and the active chat continued with its existing native model and effort. The model menu retained the native choices and offered Codex Switch. Original thread records, chat-file contents, authentication and provider/account identities were preserved. This check did not replay failed historical turns or send a new custom-provider inference.

The native reasoning picker intersects model capabilities with the signed-in account's visible-effort preference. Gemma advertised None and Medium, while this account displayed Medium alone. Changing the visibility preference updates account-wide settings even from a separate Electron user-data directory; do not change it to make an isolation test pass. Separate storage/processes also do not isolate the desktop's fixed IPC pipe.

Windows completion status must pass the stable `restart.done` message key into `SetStatus`, which translates it when rendering. Translating before `SetStatus` caused a second lookup of the displayed sentence and could record a failure after a successful restart. The production completion callback now has an offscreen regression across all bundled languages; no relaxed localization fallback is used.

The public native implementation corroborates the observed cache behavior: [`models-manager/src/manager.rs`](https://github.com/openai/codex/blob/c0cc9fc820f62e4dbdde68214dd6d792d6c8a7ee/codex-rs/models-manager/src/manager.rs) reloads a valid cache before model listing, and [`models-manager/src/cache.rs`](https://github.com/openai/codex/blob/c0cc9fc820f62e4dbdde68214dd6d792d6c8a7ee/codex-rs/models-manager/src/cache.rs) validates its age, client version and identity. This source revision is newer than the inspected installation; executable contract tests remain the evidence for that installation.

Future desktop versions may change the private IPC/query contract. Recheck native and protocol contracts before claiming support for a new version. A refresh failure is visible and must not trigger an automatic restart of active work.
