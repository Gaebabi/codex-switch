# Binary releases

[Release1.42.3](https://github.com/Gaebabi/codex-switch/releases/tag/v1.42.3) provides complete Windows x64 and macOS15+ Apple Silicon/Intel ZIPs, plus unsigned Linux x64/ARM64 DEB/RPM/tar.gz integration previews. Keep the entire folder/app bundle. No source build or global .NET installation is required; Codex desktop/CLI is installed separately. [Downloads](../README.md#download) / [latest published Release](https://github.com/Gaebabi/codex-switch/releases/latest).

Release1.42.3 integrates community PR107: Windows usage refresh recovers when an update removes the cached executable, without restarting Switch. Valid paths remain cached, rediscovery is serialized, installation gaps remain visible and submitted requests are not replayed. [Recovery and release verification](development/RELEASE_1_42_3.md). Links are staged targets until the public release and verification manifest are available.

Release1.42.2 adds account-warning browser sign-in, default-Off quota-based switching with optimal/custom priority and durable restart recovery. Subscription dates/day counts have headings, Pro tiers retain their official 100/200/500 names, and the Windows titlebar identifies the loaded version. [Behavior](development/ACCOUNT_AUTOMATION.md) / [release gates](development/RELEASE_1_42_2.md) / [native evidence](evidence/account-automation/README.md).

These packages retain the1.40.7 features: built-in CPU collection with visible download/authorization and explicit signed-driver/worker consent, plus native disk read/write gauges. The account app stays unprivileged; unknowns are never fabricated and observed throughput is not rated capacity. Reviewed dependency/history changes retain existing recovery/manual switching/eligible continuation and data identities. [CPU setup/security](TEMPERATURES.md) / [disk policy](DISK_IO.md) / [release procedure](development/RELEASE_1_41_1.md) / [actual Windows/Linux gallery](media/release-1.41.1/README.md).

Earlier1.40.2 fixes automatic startup recovery in the shared desktop: opening the app while the native keyring is locked no longer prevents every scheduled retry. The normal window starts its existing60-second clock before initialization; when the prerequisite recovers, the same guarded initialization path loads accounts without clicking Refresh. Successful initialization still gates account actions. Native provider trust, credential policy, vault/key/file identities and strict validation remain unchanged. [Actual locked/unlocked program comparison and evidence scope](evidence/automatic-startup-recovery/README.md).

Windows also includes initialization retry and atomic runtime ownership-record writing introduced in1.40.1. Manual switching, encrypted handoff checkpoints and eligible automatic local-chat continuation retain their existing behavior. [Handoff details](SWITCHING.md).

Windows/Linux packages are unsigned. Mac bundles are natively ad-hoc signed and strictly verified after ZIP extraction/staged installation; they are not Developer ID signed or Apple-notarized. Follow the app-specific first-launch guidance in [Mac setup](MACOS.md). MacBook real-device screenshot remains reserved for the maintainer; native CI is not substituted as that image.

Linux remains an integration preview with `supportedAccountHandoff:false`: approved official Debian client26.1007.71326, existing file credential policy and X11/XWayland are required. Native package/provider/UI tests and owner-operated no-chat two-account switching are distinct from authenticated active-chat continuation, booted GNOME/KDE/Wayland/ARM64 desktop and accessibility acceptance. [Linux packages and remaining gates](development/LINUX_PACKAGES.md).

Every Release supplies `SHA256SUMS.txt` and sanitized source/runtime/package `VERIFICATION.json`. Stage a draft against the reviewed merged tree, verify every uploaded GitHub SHA256/size, then publish manually; CI has read-only permissions and no signing/account/publisher secrets. Existing releases remain available. No automatic updater is configured. [1.40.1 publication receipt](development/RELEASE_1_40_1.md).
